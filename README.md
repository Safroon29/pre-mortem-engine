# Pre-Mortem Engine — Workspace 2026

Java + Spring Boot + Thymeleaf + MySQL project-risk workspace, aligned to `JAVANEW.pptx`.

## Features
- **Create Project** is a dedicated page (`/projects/create`) that saves project name, type and description only. It does not create an assessment.
- **My Projects** lists project records separately.
- **Scan Project** accepts a project ZIP or supported source/README/configuration file and scans it for rule-based signals, strengths and potential failure scenarios. You can optionally link the scan to a saved project.
- **Assessment Reports** only displays saved findings produced by project scans. It is not a manual assessment form.
- **Dynamic What-if Simulations** compares baseline and alternate probability/impact values live using the PPT model `Probability × Impact`.
- **** documents the real JPA tables and provides an executable schema script.
- **Light/Dark theme** toggle persists in the browser.
- Sidebar has its own vertical scrolling so every navigation item stays reachable on shorter screens.

## Requirements
- JDK 21 or newer compatible with the Spring Boot version in `pom.xml`
- MySQL Server 8.x
- Maven 3.6.3+

## 1. Create the new database
This version uses a fresh database name so it does not overlap the older project database. Run the full script in `src/main/resources/db/premortem_engine_workspace_2026.sql`, or run:

```sql
CREATE DATABASE premortem_engine_workspace_2026
  CHARACTER SET utf8mb4 COLLATE utf8mb4_unicode_ci;
```

Actual application tables are `app_users`, `projects`, and `risk_assessments`. The PPT's conceptual `users` and `risks` correspond to `app_users` and `risk_assessments` in this implementation. Foreign keys: `projects.user_id -> app_users.id`, `risk_assessments.project_id -> projects.project_id` (nullable for standalone scans), and `risk_assessments.owner_id -> app_users.id`.

## 2. Configure MySQL credentials
Open `src/main/resources/application.properties`. The database URL already targets `premortem_engine_workspace_2026`. Set your local username/password by editing the properties or using environment variables:

```bat
set DB_USERNAME=root
set DB_PASSWORD=your_actual_mysql_password
```

The default password placeholder is `change_me`; replace it with your own local MySQL password. Do not publish database credentials.

## 3. Run on Windows
Open Command Prompt in the folder containing `pom.xml` and run:

```bat
mvn clean spring-boot:run
```

Open `http://localhost:8080`, register, and sign in. If port 8080 is busy, change `server.port` in `application.properties`.

## 4. Demo flow
1. **Create Project** → enter project details → save. The project is saved independently.
2. **My Projects** → verify the new project is listed.
3. **Scan Project** → upload a ZIP/README/source/config file and start the scan.
4. Review the generated scan report, strengths, evidence, risk findings and prevention plan.
5. **Assessment Reports** → open the stored findings generated by the scan.
6. **What-if Simulations** → move probability/impact sliders and compare scenario scores live.
7. **** → show the three tables and their relationships.
8. Toggle light/dark theme from the sidebar.

## Risk scoring
`risk score = probability × impact`, range 1–25. Current levels: Low 1–5, Medium 6–14, High 15–25. The What-if simulator is an illustrative scenario comparison, not a statistically calibrated failure predictor.

## Scanner limitations
The scanner uses transparent source/configuration heuristics; it does not execute uploaded code or call a hosted LLM. Findings are leads to investigate, not guaranteed vulnerabilities. A lack of detected signals does not prove the project is safe. The upload is inspected in memory and not stored as a project artifact. Upload size is limited by Spring's multipart settings.

## Notes
- `spring.jpa.hibernate.ddl-auto=update` lets Hibernate create/update tables on startup. The included SQL is useful for first-time setup and demonstrating the schema.
- Project files are not automatically attached to a project record; the project register and scan workflow remain distinct actions.
- Configure HTTPS, database credentials, backups and stronger production error handling before deployment.


What-if Simulations can use a saved assessment report or analyze a supported project ZIP/text file to suggest project-specific questions. Scenario sliders compare probability × impact scores without modifying saved reports.


## Create Project page

After signing in, use **Create Project** in the sidebar or open `http://localhost:8080/create-project`. The form saves a project name, project type, and description to the signed-in user's MySQL-backed project list. It also supports one optional supporting document (`.doc`, `.docx`, `.pdf`, `.txt`, `.md`, `.rtf`, up to 10 MB). Uploaded documents are stored in the app's `uploads/projects/<project-id>/` folder and can be downloaded from that project's details page. The app creates/updates the new document metadata columns automatically through `spring.jpa.hibernate.ddl-auto=update`.
